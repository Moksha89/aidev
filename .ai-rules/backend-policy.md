# Backend coding policy

This rule activates only after the human has approved the frontend.
Backend paths are now writable, but several categories remain forbidden.

## Allowed paths

```glob
apps/api/**
backend/**
server/**
api/**
controllers/**
models/**
schemas/**
services/**
repositories/**
db/**
database/**
migrations/**
alembic/**
prisma/**
tests/**
```

## Forbidden paths (still)

```glob
**/.env
**/.env.production
**/.env.staging
**/secrets/**
**/credentials.*
.github/workflows/deploy*.yml
.github/workflows/release*.yml
infra/production/**
docker/Dockerfile.sandbox
.ai-rules/**
```

## Required practices

- Every new endpoint must have a Pydantic (or equivalent) request/response
  schema. No untyped `dict` bodies.
- Every state-mutating endpoint must be wrapped in a database
  transaction.
- Every new endpoint must include an integration test under `tests/`.
- Migrations must be generated by the project's tool (Alembic for the
  reference stack). Do not hand-edit auto-generated migration files
  beyond renaming if necessary.
- Any new external HTTP client must use the platform's existing client
  factory (timeouts, retries, structured logging). Do not import `requests`
  ad-hoc.

## Forbidden practices

- Adding a route that returns user data without an auth check.
- Logging request bodies that may contain secrets, tokens, or PII.
- Running shell commands or filesystem mutations from request handlers.
- Reading environment variables outside the configuration module.
- Disabling or bypassing the platform's rate limiter.

## Required reviewer

Tasks in this phase must additionally pass the **Security Reviewer**
agent before the PR is opened. The Security Reviewer runs `semgrep`,
`bandit`, and the platform's custom rule pack.
