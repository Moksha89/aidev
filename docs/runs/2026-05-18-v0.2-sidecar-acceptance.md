isolation](https://github.com/Moksha89/aidev/pull/5) ·

Acceptance probe: `workers/sandbox-runner/scripts/pass2_docker.py`

host Docker daemon. 13/13 checks **PASS**.

## What changed since the PR #4 acceptance

- The agent container's `NetworkMode` was a per-task bridge but with
  `internal: false` (PR #4) — direct outbound from the sandbox was
  *cooperatively* blocked by env vars, not by the kernel.
- v0.2 splits the per-task network into **two**:
  - `aidev_sandbox_<task>` — `internal: true`, no MASQUERADE, no
    default gateway. Agent + egress-proxy alias live here. Nothing
    else.
  - `aidev_pub_<task>` — plain bridge. Only the forwarder sidecar
    lives here, so docker-proxy can deliver host:31xxx → :3000.
- A new per-task `aidev/forwarder:latest` sidecar (alpine + `socat`,
  UID 10002, no caps, no volumes) is multi-homed on both networks
  and proxies preview traffic into the agent.
- Cleanup is now: forwarder → disconnect egress-proxy from sandbox
  net → agent → volume → sandbox net → pub net.

## Test environment

- Host: Ubuntu Server 24 LTS, single tenant after PR #4 cleanup.
- Docker: rebuilt `infra-sandbox-runner` image from `devin/v0.2-...`,
  `aidev/forwarder:latest` built from `docker/Dockerfile.forwarder`.
- The pass2 probe was `docker cp`'d into the runner and executed with
  `docker exec --user 0 -e PYTHONPATH=/app -w /app`.

## Open follow-ups (not blockers for v0.2)

1. **PR #4 prerequisite fixes are still on `devin/1779115457-...` and
   not yet on `main`.** The platform requires those (bcrypt pin,
   PEP-668 `--break-system-packages`, `${VAR//-/_}` dash-shell fix,
   `AIDEV_REDIS_URL` env aliasing) just to boot. The VPS deployment
   used to drive this acceptance run had them applied as a local
   stash on top of the v0.2 branch checkout; they did NOT get
   committed onto v0.2. They should ride into `main` either by
   merging PR #4 first or by being folded into the v0.2 merge.
2. **`workers/sandbox-runner/scripts/` is not copied into the
   `infra-sandbox-runner` image.** The probe had to be `docker
   cp`'d in. If we want this script to be in-image for repeat runs
   we'd add a `COPY workers/${WORKER}/scripts ./scripts` to
   `docker/Dockerfile.worker`.
3. **Sandbox-runner is built without docker-socket access for the
   non-root UID.** The probe ran as `--user 0` to talk to the host
   socket. The real orchestrator code path will need a thought-through
   answer for how a constrained worker UID can manage host containers
   without effectively becoming root on the host (typical fixes:
   socket-only proxy / rootless Docker / DinD). This is the same
   trade-off PR #4 documented; v0.2 does not change it.
4. Forwarder image is currently unbuilt by compose; deploy steps need
   `docker build -f docker/Dockerfile.forwarder -t aidev/forwarder:latest .`
   before the executor will work.
